# Handoff Log

Running log, updated roughly every 100 AI credits spent (see [model_rate.md](./model_rate.md)). Credit figures are estimates from token volume.

## Decisions (beyond SPEC/PLAN)
- Sleep color: indigo `#4f46e5`. Sleep is excluded from "awake %" stats.
- No Java on the dev machine, so the Firestore emulator can't run locally. Rules tests are written and will run in CI (which has Java).
- `@firebase/rules-unit-testing@^6` (v5 needs firebase 12). Settings rule fields are optional but validated, and `v==1` is required.
- No Firebase project yet. `.env.local` holds placeholders. **Demo mode** (`VITE_DEMO=true`) swaps in fake auth and an in-memory repo so the UI can be exercised locally.
- Saves wait for a server-confirmed snapshot (not cache-only), unless offline or after a 4s grace period. This prevents overwriting real docs from a partial cache.
- Tapping a marble in the current hour clamps the default duration so it doesn't run into the future.
- Rules deploy runs in `ci.yml` only after the `check` and `rules` jobs pass, and only when `firestore.rules`/`firebase.json` change. A manual `deploy-rules.yml` (workflow_dispatch) also exists.
- Future slots render as empty, even inside the sleep window (precedence: logged > future → empty > sleep > unlogged gray).
- A slot is loggable once it has started (slot start ≤ now).
- The sleep window applies within each calendar day, wrapping (23:00–07:00 means 00:00–07:00 and 23:00–24:00 on each day).
- Stage 2 visual direction (user choice): soft and friendly (glass jar, glossy marbles, warm off-white) with a bottom tab bar.
- Local `.env.local` is now real Firebase (`VITE_DEMO=false`). For agent smoke tests, run `VITE_DEMO=true npm run dev`.
- GitHub setup is deferred until after Stage 1 (user request): the CI workflow is written but not pushed.
- **App Check is never enforced** (user, 2026-10-18, iOS question N2). The free-team iPhone app can't attest. The web keeps its reCAPTCHA in monitor-only mode, and PLAN 4.3 step 6 is cancelled.
- **Sign-ups:** the user will turn off "Enable create (sign-up)" in the Auth console after both clients are signed in. This blocks only new email/password accounts; first-time Google sign-ins still create users. Web follow-up W8 maps `auth/admin-restricted-operation` to friendly copy.
- **Stage 5 drop start (user, 2026-10-20):** a drag-to-drop writes **1 hour starting at the first unlogged slot after the latest logged slot today**, so repeated drops catch up hour by hour. Sleep counts as logged (the gap starts after sleep ends). Look back over **today only**; if nothing is logged today, start at sleep end or 00:00. If there's no gap, fall back to the current last-hour overwrite with Undo. The Log time sheet's default is unchanged.
- **Stage 5 redesign (user, 2026-10-20):** a pastel, playful overhaul of the **whole app**. Categories become pastel versions of the same hues (Wasted becomes muted slate or lavender-gray, still clearly the darkest). Dark mode is redesigned as pastel-on-dusk. Fun comes from **bouncier micro-animations** only (no new font, confetti, illustrations, or textures). The designer shows **2–3 static Day-screen mockups** before the build plan.
- **Stage 5 one line per entry (user, 2026-10-20):** back-to-back same-category logs must stay separate lines in the Entries list. **Store entry boundaries** in the day doc (new field), so each log or drop is its own line with its own edit, delete, and note. Rules, rules tests, and the iOS codec are updated with it. Existing days without boundary data display as merged runs, as today. The jar does not show boundaries (Entries list only).
- **Stage 5 engineering answers (user, 2026-10-20):** a different-category repeat drop **advances** to the next gap (Undo fixes mistakes). A 30-minute gap logs a **half marble**. Evening sleep that has already started counts as **unlogged** (only morning sleep is a boundary). The **iOS port is deferred**, so the iOS workflow is expected to go red after Stage 5 until then. Local Swift tests are blocked until the user accepts the Xcode license.
- **Stage 5 design picks (user, 2026-10-20):** **Sorbet** direction. Sleep moves to periwinkle `#9aa6f4` (update SPEC section 2 and AGENTS conventions when building). Tray wobble every 8s, today only, stopping while dragging. Split-marble hour numbers use dark ink with a light halo.
- **Sleep anchors for drops (PM, 2026-10-20, from the code review):** a sleep slot anchors the catch-up only if it's morning sleep that has started. For wrapping windows that's `[0, end)`. A non-wrapping window counts as morning sleep only if it ends by 12:00; otherwise (a nap or evening window) it never anchors and fills like unlogged time.
- **iOS client** (planning only, [ios/](./ios/README.md)): iPhone 16 target, bundle ID `com.dd123zzz.marbles`, local system notifications (no `.ics` on iOS), theme stays synced through the settings doc. No data-model or rules change.
